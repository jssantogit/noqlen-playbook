# Specs And ADRs

Specs are required for:

- Non-trivial behavior.
- Public API changes.
- File operation changes.
- App/core boundary changes.
- Security-sensitive behavior.
- Data model changes.
- Release process changes.

ADRs are required for:

- Architectural decisions.
- Hard-to-reverse decisions.
- New dependencies.
- Storage strategy.
- Public API strategy.
- App/core boundary strategy.
- Security policy changes.

ADRs are not required for simple implementation details. If a choice is easy to reverse and does not affect public contracts, document it in the spec or handoff instead.
